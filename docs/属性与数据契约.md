# 属性与数据契约

跨变体组合性的根基。**变体之间不直接引用，只通过属性字典、共享地图数据和表达式函数沟通。** 因此属性名是规则库的"公共 API"。

## 公共属性（内核/各变体约定）

| 属性 | 类型 | 含义 | 谁读 |
|---|---|---|---|
| `name` | string | 显示名 | 内核/日志 |
| `owner` | int | 归属玩家编号（0 起） | 内核/counter/victory |
| `strength` | number | 战斗力（攻防共用） | counter（`effStr`）/combat |
| `move` | number | 完整移动力 | turn（`effMove` 重置） |
| `moveLeft` | number | 本行动剩余移动力 | movement/turn |
| `acted` | int(0/1) | 本回合是否已行动 | 内核/turn |
| `type` | string | 部队类型（general/infantry/...） | 展示/自定义 |
| `faction` | string | 势力标签（red/blue/...） | 展示 |
| `entryTurn` | int | 援军进场回合（缺省不在场） | scenario/turn |
| `entryHex` | int[2] | 援军进场格 [q,r] | scenario/turn |
| `key` | string | 算子键（对应 units.json 键） | counter/scenario |
| `hex` | int[2] | 初始部署格 [q,r]（scenario 里用） | scenario |
| `penaltyStrength` | number | 受损面战力扣减（damage 写入） | counter |
| `penaltyMove` | number | 受损面移动力扣减（damage 写入） | counter |
| `steps` / `maxSteps` | int | 当前/满编步数（counter/stepped） | counter |
| `damage` | int | 损伤点数（counter/damageTrack） | counter |
| `eliminated` | int(0/1) | 已被歼灭（`eliminate` 效果写入） | victory/attrition |
| `exited` | int(0/1) | 已退场（`exit` 效果写入） | victory/exit |
| `entrenched` | int(0/1) | 已构筑工事（自定义 `setattr` 写入） | combat |

`damage` 在 `game.json` 声明（默认 `{ strengthPenalty:1, movePenalty:1 }`），加载时写入每个算子的 `penaltyStrength/penaltyMove`；`effStr(counter)` = `strength - (背面? penaltyStrength : 0)`。

## 自定义属性

游戏可以定义自己的属性键（例如士气 `morale`、军团 `legion`），规则表达式里 `counter.xxx` 直接可读。`verify` 会汇总四类名字（根变量、上下文变量、算子属性、州变量）成 `NameContract`，对表达式里用到的未知名字给出 **warning**（不是 error）；自定义属性无需前缀，只要在 `units.json`、`setattr`、`turnReset` 或变体的 `INameContributor` 里出现过即可。

> 引擎控制流用到的少数名字可被 `game.json` 覆盖：`turnResetPhase`（默认 `"action"`，该阶段开始时执行 `turnReset`）、`actedAttr`（默认 `"acted"`）、`moveBlockedWhenBack`（默认 `true`）。其余公共属性名由 `ContractNames` 集中定义。

## 地形/地图数据（GridMap，共享只读）

| 数据 | 来源表 | 提供函数 |
|---|---|---|
| `TerrainAt(hex)` | map.json `terrain` | `terrainAt(pos)` |
| `TerrainCostAt(hex)` | movement.json `terrainCost` | `terrainCost(pos)` / `moveCost(a,b)` |
| `TerrainDefenseAt(hex)` | movement.json `terrainDefenseBonus` | `terrainDefense(pos)` |
| `RiverCost(a,b)` | map.json `rivers` + movement.json `riverCrossCost` | `riverCost(counter,pos)` |
| `IsVictoryHex(hex)` | map.json `victoryHexes` | `isVictoryHex(pos)` / `vpHeld(me)` |

## 表达式函数（按提供方）

- **内核**：`dist/adjacent/occupied/inBounds/hasattr/attr/owner/onboard/isback/isfront/notacted/effStr/effMove/enemycount/friendlycount/if/not/min/max/abs/...`
- **map/hexGrid**：`terrainAt/terrain/terrainCost/terrainDefense/isVictoryHex`
- **map/pointToPoint**：`terrainAt/terrain/terrainDefense/nodetype/controllednodes/occupiedby`（节点城防、势力控制城镇数）
- **movement/movePoints**：`moveCost/riverCost`
- **movement/roadNetwork**：沿道路 BFS 可达（无新增表达式）
- **victory/vpAndSudden**：`vpHeld/victoryheld`
- **cards/standard**：`handsize(player)` / `handlimit()`
- **stacking/&#42;**：`stackcount(pos)` / `stacklimit()`（0=不限）
- **counter/&#42;**：`effStr/effMove`（由所选 counter 变体提供），`steps(counter)`（stepped），`damageValue(counter)`（damageTrack）
- **control/zoc**：`inZoc(pos)` / `zocOwner(pos)` / `zocProjected(counter)`
- **control/controlPoints**：`hexControl(pos)` / `controlledBy(pos,owner)` / `controlledCount(owner)`；效果 `control`（别名 `capture`）
- **supply/traceLine**：`inSupply(counter)` / `outOfSupply(counter)` / `supplyDistance(counter)` / `isSupplySource(pos)`
- **combat/oddsShift**：配置项 `shifts:[表达式]` 加到骰列
- **combat/stepLoss**：结算后写 `attLoss` / `defLoss`（双方步损）
- **victory/objectives**：`objectivesHeld(player)` / `objective(pos)`；**victory/exit**：`exitedStrength(player)`；**victory/attrition**：`destroyedStrength(player)` / `lostStrength(player)`

## 点对点地图（spacemap.json）

| 数据 | 来源 | 提供 |
|---|---|---|
| `nodes[].attributes.faction` | spacemap.json | 初始领地（写入 `GameState.SpaceControl`） |
| `nodes[].attributes.type` | spacemap.json | `nodetype(pos)` |
| `nodes[].attributes.defense` | spacemap.json | `terrainDefense(pos)`（战斗行表达式扣除守方城防） |
| `edges[]` | spacemap.json | 邻接/`dist`（每段 1 跳）；`control` 效果写 `SpaceControl` |
| `scenario.units[].node` | scenario.json | 按节点部署；单位 `faction` 覆盖该节点控制权 |

## 卡牌数据契约（cards.json）

- `cards`：`{ id: { name, kind(action|event), value, text, effects[] } }`；`kind` 由规则（game.json）解释，引擎只提供 `ctx.Vars["card"]/["cardValue"]/["cardKind"]`。
- `decks`：`{ deckId: { entries: [ { card, count } ] } }`；引擎启动时按条目展开为 `GameState.Cards`。
- 区域 `CardZone`：`Deck/Hand/Discard/Played/Removed`。出牌由 `needsCard` 行动驱动，牌从手牌 → `Played`；`discard`/`shuffle` 效果改变区域，抽牌在牌库空时回收 `Played/Discard`。
- 效果：`draw{deck,count,player}`、`replenish{deck,player}`（补至手牌上限）、`shuffle{deck}`、`discard`、`roll{key,count,sides}`（写入 `state.vars[key]`）。
- 手牌上限：cards.json 根级 `handLimit`（0=不限）。`draw` 不会超过上限；`replenish` 补到上限。表达式可用 `handsize(player)` / `handlimit()`。

## 堆叠（stacking 子系统）

- `game.json` 的 `rules.stacking` 选择变体：`unlimited`（默认，一格不限）或 `perHex`（`config.maxPerHex` 个/格）。
- 引擎对任何带 `needsPosition` 的行动统一执行堆叠上限校验；超限即拒绝（"该格已堆满"）。
- 规则表达式可用 `stackcount(pos)`、`stacklimit()`。
- App 的**堆叠选择**是通用的：同格多算子时自动扇出显示，点击弹出选择面板（`堆叠 · 选择算子`），可从被压住的算子中任选一枚——对六角格与点对点地图同样生效。
- 抽牌与 `roll` 用 `GameDefinition.seed` 播种的确定性 RNG（`wpe play` 可复现）。

规则表达式里出现的函数必须在 `verify` 时已注册，否则报"未知函数"。这意味着**换变体时，只要新旧变体提供的函数名一致，规则无需改动**。

## 控制与补给（control / supply 子系统）

- `control` 变体：`off`（默认，中性函数）/ `zoc`（控制区）/ `controlPoints`（按格记录归属 + `control`/`capture` 效果）。
- `control/zoc` 配置：`projectTypes` / `stopOnEnter` / `exitCost` / `noProjectAcrossRiver` / `noProjectTerrain`；由 movement 变体通过 `IControlModule` 接口读取。
- `control/controlPoints`：控制权写入 `GameState.Control`，键为 `IMap.CellKey`（六角格 `"q,r"`，点对点为节点 id）。
- `supply` 变体：`off`（默认，恒在补给）/ `traceLine`（补给线）。`traceLine` 配置 `sources`（按 owner 的 `"q,r"` 列表）、`range`、`costBudget`、`blockedByEnemyUnit`、`blockedByEnemyZoc`、`allowedTerrain`。按需计算，可直接用于 `turnReset` 表达式（如断补扣移动力）。
- 示例包：`games/lab-zoc`、`games/lab-supply`、`games/lab-steploss`、`games/lab-objectives`。

## 通用效果（内核）

`move/flip/remove/retreat/setattr/setside/setvar/addvar/log/endphase/pass/roll/advance/eliminate/reveal`。

- `advance`：推进到目标原格（目标已被击退/歼灭时）；被占据则不动。
- `eliminate`：下阵并写入 `eliminated`（供 `victory/attrition` 统计）。
- 子系统效果：`control`/`capture`（control）、`steploss`（counter/stepped）、`damage`（counter/damageTrack）、`exit`（victory/exit）。

## 行动定义（game.json moves）的 kind 约定

| kind | 语义 | 内核用它做什么 |
|---|---|---|
| `movement` | 逐格移动，扣 moveLeft | 可达区域计算、自动结束行动 |
| `combat` | 掷骰+CRT 结算 | 攻击目标计算 |
| `recover` / `pass` | 结束该算子行动 | 结束行动 |
| （空） | 全局行动（如 endphase） | 全局合法行动 |

App 只按 kind 生成交互（可去点高亮 / 可攻击目标高亮 / 按钮），不认具体行动 id——这是 UI 与具体棋解耦的关键。
