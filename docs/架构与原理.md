# WPE 架构与原理

目标：一台"能吃兵棋规则"的通用引擎。每款棋 = **一个游戏包（纯数据表）**，中台读懂每张表的语义、在后台编排好规则并执行。**引擎零游戏代码**。

## 技术栈

C# / .NET 8 · System.Text.Json(表解析) · 表达式语言(小众规则 DSL) · C#接口(逃生门 hook)。
项目名 WPE = Wargame Pipeline Engine（区别于旧 ZunTzu 系的 ZT 命名）。

## 分层（依赖单向向下）

```
src/Wpe.Core     内核（中台）：状态模型 · 表达式语言 · 效果原语 · 模块宿主 · 编排器 GameEngine
src/Wpe.Rules    规则库：各子系统变体实现（算法） + 包加载器 PackageLoader（组合/校验）
src/Wpe.Render   渲染：白板算子渲染器（名字/势力色/数值），批量出图与 GUI 共用
src/Wpe.App      GUI：SkiaSharp 渲染 + 双人热座（按 move.kind 交互，复用 Wpe.Render）
src/Wpe.Cli      命令行：verify / play / counters / rule list / new
games/<棋>/      每棋一份，纯数据表
rules/families/<家族>.json       家族预设（分类 -> 变体）；rules/<分类>/<变体>/  权威元数据（variant.json / config.schema / tests/）
```

**铁律**：`src/Wpe.Core` 与 `src/Wpe.Rules` 中不允许出现任何具体游戏的专属代码；新棋 = 新建 `games/<名字>/` 目录，只填表。

## 核心创意：正交规则 × 能力组合

兵棋规则是一组**相互独立（正交）的机制轴**，差异多在算法结构而非参数。所以引擎把规则拆成一个个**规则变体**，由 **能力（capability）** 驱动组合：

- **规则 = 一个成熟算法实现（实现若干接口）+ 自己的 JSON 配置 + 元数据**。
- 规则声明 `Provides`（提供的能力/函数/效果）与 `Requires`（依赖的能力）。
- 能力分三类：
  - **独占能力**（算法面）：最多一个提供者，第二个报错。`map / counter / movement / combat / dice / turn / stacking / scenario / cards / zoc / territory / supply`。
  - **贡献**（函数/效果）：按名唯一，跨规则重名报错（可声明 `overrides`）。
  - **终局条件**：由内核统一判定 `endConditions`，因此胜利规则只是函数贡献，可任意叠加。
- **分类（`rules/<分类>/`）= 命名空间/显示分组，不参与互斥**。同类目可多选，只要它们提供不同的独占能力（如 `zoc` 与 `territory`）。

默认装配用 `family: "default"`；`game.json` 的 `rules` 逐分类覆盖（值可为对象或数组）。长期目标：每个能力积累十几变体，新游戏 = 选一组规则。

| 分类 | 职责 | 默认变体 |
|---|---|---|
| `map` | 几何/地形/河流/胜利点 | `hexGrid` |
| `counter` | 算子目录/单位模型 | `generic` |
| `zoc` | 控制区投影（仅此） | `off` |
| `territory` | 格子/节点归属（仅此） | `off` |
| `supply` | 补给线 | `off` |
| `movement` | 移动费/可达区域 | `movePoints` |
| `combat` | 战力比 CRT 结算 | `crTable` |
| `dice` | 掷骰 | `d6` |
| `turn` | 回合重置 | `phases` |
| `scenario` | 剧本/部署/援军 | `generic` |
| `victory` | 终局辅助函数 | `vpAndSudden` |
| `stacking` | 堆叠上限 | `unlimited` |

**正交感示例**：`zoc`（控制区）与 `territory`（归属）是两个不同的独占能力，可同时启用；`objectives` + `attrition` 是终局函数贡献，可同时选用；只有两个 `combat` 这类同能力实现才会被拦截。旧设计把归属与 ZOC 塞进同一个 `control` 分类导致互斥——那是把分类错当成了机制，已修正。

## 变体生命周期

```csharp
interface IRuleVariant {
    VariantInfo Info { get; }                    // 元数据：分类/id/状态/requires/provides/requiresVariants/overrides
    void Load(string? configJson, GameDefinition def);   // 解析自己的表
    void Register(ModuleHost host);              // 注册函数/效果/接口
    void Apply(GameState state, GameEngine? engine);     // 对已构建的状态生效（部署/费用合并）
    void Validate(GameDefinition def, List<string> issues); // 校验配置，报错带位置
}
```

`RuleVariantBase` 提供上面 4 个方法的空实现，新变体只覆写需要的部分。可选的 `INameContributor` 让变体上报自己声明的属性/变量名（汇入 `NameContract`）。独占能力接口：`IMovementModule`（可达/费用）、`ICombatModule`（结算）、`IDiceModule`（掷骰）、`ITurnModule`（回合重置/援军）、`ICounterModule`（单位模型）、`IZocModule`（控制区）、`ISupplyModule`（补给）、`IStackingModule`（堆叠）。`ModuleHost` 是注册中心：规则表、函数表、效果表、独占接口、战斗表字典。

## 跨规则耦合的契约（为什么变体可以随意互换）

规则之间**不直接引用**，只通过三样东西沟通：

1. **属性字典契约**（见 `属性与数据契约.md`）：`strength/move/moveLeft/acted/owner` 等是公共 API，`units.json` 由 schema 约束。
2. **共享数据**：地图数据由 `map` 提供，其他规则只读；领地归属由 `territory` 写 `GameState.Territory`。
3. **表达式语言**：规则把自己的能力暴露为表达式函数（`moveCost/riverCost/terrainAt/vpHeld/effStr/inZoc/inSupply...`），规则作者在 validators/effects/endConditions 里组合它们。

换一个 `movement` 变体，只要它还提供 `moveCost/riverCost` 函数，其他规则就不受影响。

## 引擎管线（GameEngine 是薄编排器）

```
Apply(moveId, counter, pos, target):
  阶段/字段校验 → counterFilter/targetFilter/validators（表达式求值）→ hook.Validate
  → 掷骰（dice 接口，roll 入 ctx.Vars）
  → 结算（combat 接口 → CRT → result 码入 ctx.Vars）
  → 效果（when 门先全部求值再逐个应用；内核效果 + 规则注册的效果）
  → resultEffects[result码]
  → hook.OnAfterMove → 触发 moveApplied 触发器
  → 自动结束行动（autoActWhenExhausted + 无可行动）
  → 终局判定（内核遍历 endConditions）
```

可达区域与攻击目标也走接口：`ReachablePositions` → `IMovementModule.Reachable`，`TargetCountersForMove` → 通用目标过滤。GUI（`src/Wpe.App`）只认 `move.kind`（movement/combat/recover/pass），不认行动 id——换任何游戏包都能跑。

## 包加载顺序（PackageLoader）

```
game.json 反序列化（rules 值可为对象或数组）
→ 读 rules/ 目录（RuleCatalog）+ 反射扫描代码变体（VariantRegistry）→ 1:1 对账
→ 解析 family 预设 + rules 覆盖 → 一组规则实例
→ 按能力排序（独占能力序，贡献最后）→ 实例化 → Load(表内容) → Register(host)
→ 组合校验（能力依赖 / 独占冲突 / requiresVariants / 未知变体 / 重名函数效果）→ 规则 Validate
→ 汇总名字契约（内核 + 变体 INameContributor + game.json 的效果键）
→ 表达式全量预编译（语法 error + 未知函数 error + 未知名字 warning + 语义 lint）
→ 构建 GameState（map 数据入 state）
→ 按同一能力序 Apply（map → counter → scenario → zoc/territory → cards → movement）
→ damage 惩罚写入各算子 → hook 解析 → new GameEngine
```

## CLI

- `wpe verify <包>`：完整校验（表结构/表达式/组合/边界/河流连通），报错带位置。`verify` 绿 = 中台能读懂你的表。
- `wpe play <包>`：无头自动对局（双方按"就近攻击/推进"行动），回归冒烟。
- `wpe counters <包> [输出目录]`：批量生产**白板算子**（势力色块 + 名字 + 攻/移数值），正面 + 受损面 + 总表，输出到 `<包>/art/`（默认）。渲染逻辑在 `src/Wpe.Render`，GUI 复用同一渲染器。
- `wpe overlay <包> [输出.png] [--nums]`：把地图（地形/河流/胜利点/算子）渲染成 PNG，快速核对地图与演示。
- `wpe river <包> <"q,r" ...> [--fords 0,2] [--append]`：**快速生成河流**——按相邻六角格路径生成连通河流边（`RiverPathGenerator`），自动校验邻接，写回 map.json 后自校验。河流必须沿相邻格之间的边延伸，坏路径被拦截。
- `wpe rule list`：读取 `rules/**/variant.json` 列出规则库全部变体。
- `wpe new <名>`：生成可填写的游戏包模板并自校验。
- `Wpe.App [游戏包]`：图形界面（双人热座），复用 Wpe.Render 画算子与地图。
