# 规则库（WPE 长期核心资产）

> 长期目标：**每个主要子系统积累十几种成熟可靠的变体**，设计新游戏时通过 `game.json` 编排即可拼出大量不同的、被反复验证的规则组合。

## 库的形态

```
rules/families/<家族>.json   家族预设：子系统 -> 变体 id（game.json 的 family 字段选它）
rules/<子系统>/<变体>/
  variant.json        元数据：id/版本/状态/描述/requires/provides/configSchema
  config.schema.json  该变体配置表的字段说明
  tests/              per-variant 测试夹具（迷你剧本 + 期望结果），由 verify/CI 全量跑
src/Wpe.Rules/        变体的代码实现（继承 RuleVariantBase，实现接口）
```

`wpe rule list` 读取 `rules/**/variant.json` 列出全部变体。平台启动时反射扫描代码里的变体实现，并与磁盘做 1:1 对账。每个变体都要满足"成熟可靠"的两条硬标准：

1. **有测试夹具**：`tests/` 下放一个小剧本 + 期望结果，能无头跑、能断言。
2. **有契约**：它提供的表达式函数名（`moveCost/riverCost/...`）写进 `provides`，供其他变体和规则作者依赖。

| 子系统 | 现有 | 待积累（示例） |
|---|---|---|
| map | hexGrid · pointToPoint | squareGrid · area |
| counter | generic · stepped · damageTrack | traits · leader |
| control | off · zoc · controlPoints | zoneControl · supplyControl |
| supply | off · traceLine | zoneControl · depotStub |
| movement | movePoints · roadNetwork · zoc | road · rail · airDrop · overrun · exploit |
| combat | crTable · oddsShift · stepLoss | differential · oddsPct · dicePool · subtable |
| dice | d6 | 2d6 · d10 |
| turn | phases | impulse · cardDriven · simultaneous |
| victory | vpAndSudden · objectives · exit · attrition | timed · capitol |
| cards | standard | opsEvent · discardPile · draft |
| stacking | unlimited · perHex | transport |
| events | （无） | off · deck · weather |

## 如何新增一个变体（不改核心代码）

1. 在 `src/Wpe.Rules/<子系统>/` 写一个类继承 `RuleVariantBase`（+ 需要的接口），在 `Info` 里声明 `Subsystem`/`Id`/`requires`/`provides`。
2. 在 `rules/<子系统>/<变体>/` 写 `variant.json` + `config.schema.json` + `tests/` 夹具。
3. `wpe verify` 自检：**平台反射发现代码里的变体，并与 `variant.json` 1:1 对账**；再查 requires/provides 组合、表达式函数与名字、夹具。

冷门/客制化规则：`game.json` 的 `hookType` 指向一个 C# `IHook` 实现（行动前后钩子）。开源 + AI 辅助下，写一个变体或 hook 的成本很低。

## 组合校验（verify 在加载时拦下坏组合）

- 代码里的变体实现与磁盘 `variant.json` 必须 1:1 对应；
- 每个变体的 `requires` 子系统必须被启用，`requiresVariants`（如 `map:hexGrid`）必须匹配；
- 有掷骰/战斗/移动行动时，对应接口必须存在；
- 表达式里的函数必须已注册（error）；
- 表达式里引用的名字必须在 `NameContract` 中（未知 → warning）；
- 剧本部署格/进场格必须在地图内。

这些防线保证：**配置写错是在 `verify` 时报错，不是开一局才炸**。
