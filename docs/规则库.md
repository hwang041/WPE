# 规则库（WPE 长期核心资产）

> 长期目标：**每个主要子系统积累十几种成熟可靠的变体**，设计新游戏时通过 `game.json` 编排即可拼出大量不同的、被反复验证的规则组合。

## 库的形态

```
rules/<子系统>/<变体>/
  variant.json        元数据：id/版本/状态/描述/requires/provides/configSchema
  config.schema.json  该变体配置表的字段说明
  tests/              per-variant 测试夹具（迷你剧本 + 期望结果），由 verify/CI 全量跑
src/Wpe.Rules/        变体的代码实现（实现接缝接口）
```

当前 default 预设内置 8 个变体（见 `wpe rule list`）。每个变体都要满足"成熟可靠"的两条硬标准：

1. **有测试夹具**：`tests/` 下放一个小剧本 + 期望结果，能无头跑、能断言。
2. **有契约**：它提供的表达式函数名（`moveCost/riverCost/...`）写进 `provides`，供其他变体和规则作者依赖。

## 变体成长路线

| 子系统 | 现有 | 待积累（示例） |
|---|---|---|
| map | hexGrid | squareGrid · area · pointToPoint |
| movement | movePoints | zoc · road · rail · airDrop |
| combat | crTable | differential · oddsPct · dicePool · subtable |
| dice | d6 | 2d6 · d10 · cardDeck |
| turn | phases | iwphases · cardDriven · simultaneous |
| victory | vpAndSudden | vpOnly · milestones |
| supply | （无） | off · traceLine · zoneControl |
| stacking | （无） | unlimited · perHex |
| events | （无） | off · deck · weather |

## 如何新增一个变体

1. 在 `src/Wpe.Rules/<子系统>/` 写一个类实现 `IRuleVariant`（+ 需要的接缝接口）。
2. 在 `DefaultFamilies.Create` 注册 `(subsystem, variantId)`。
3. 在 `rules/<子系统>/<变体>/` 写 `variant.json` + `config.schema.json` + `tests/` 夹具。
4. `wpe verify` 自检：requires/provides 组合、表达式函数、夹具能跑。

冷门/客制化规则：`game.json` 的 `hookType` 指向一个 C# `IHook` 实现（行动前后钩子）。开源 + AI 辅助下，写一个变体或 hook 的成本很低。

## 组合校验（verify 在加载时拦下坏组合）

- 每个变体的 `requires` 子系统必须被启用；
- 有掷骰/战斗/移动行动时，对应接缝必须存在；
- 表达式里的函数必须已注册；
- 剧本部署格/进场格必须在地图内。

这三道防线保证：**配置写错是在 `verify` 时报错，不是开一局才炸**。
