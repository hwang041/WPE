# 规则库（WPE 长期核心资产）

> 长期目标：**每个主要子系统积累十几种成熟可靠的变体**，设计新游戏时通过 `game.json` 选一组规则即可拼出大量不同的、被反复验证的规则组合。

## 核心：规则按“能力”组合，而不是按“分类”互斥

一款游戏 = **一组规则实例**。规则声明自己**提供哪些能力、依赖哪些能力**；平台按能力组合。分类（`rules/<分类>/<变体>/` 的目录名）只是命名空间与显示分组，**没有任何互斥含义**。

能力分三类：

| 类别 | 语义 | 冲突规则 | 例 |
|---|---|---|---|
| **独占能力** | 一种算法实现只能有一个 | 两个提供者 → 组合报错 | `map` `counter` `movement` `combat` `dice` `turn` `stacking` `scenario` `cards` `zoc` `territory` `supply` |
| **贡献（函数/效果）** | 按名唯一 | 不同规则重名 → 报错（除非声明 `overrides`） | `effStr` `moveCost` `hexControl`；效果 `control` `steploss` |
| **终局条件** | 由内核统一判定 | `endConditions` 恒为数据 | `vpHeld` `objectivesHeld` `destroyedStrength` 等函数可任意叠加 |

**关键分野**：`zoc`（控制区投影）与 `territory`（格子/节点归属）是两个不同的独占能力，因此**可以同时启用**；`victory` 系列只是函数贡献，所以 `objectives` + `attrition` 可同时启用。只有同能力的第二实现（如两个 `combat`）才会被拦截。

## 库的形态

```
rules/families/<家族>.json   家族预设：分类 -> 变体 id（值可为数组，game.json 的 family 选它）
rules/<分类>/<变体>/
  variant.json        元数据：id/版本/状态/描述/requires/provides/overrides/configSchema
  config.schema.json  该变体配置表的字段说明
  tests/              per-variant 测试夹具（迷你剧本 + 期望结果）
src/Wpe.Rules/        变体的代码实现（继承 RuleVariantBase，实现接口）
```

`wpe rule list` 读取 `rules/**/variant.json` 列出全部变体。平台启动时反射扫描代码里的变体实现，并与磁盘做 1:1 对账。每个变体都要满足“成熟可靠”的两条硬标准：

1. **有测试夹具**：`tests/` 下放一个小剧本 + 期望结果，能无头跑、能断言。
2. **有契约**：它提供的表达式函数名（`moveCost/riverCost/...`）写进 `provides`，供其他变体和规则作者依赖。

## 如何新增一个变体（不改核心代码）

1. 在 `src/Wpe.Rules/<分类>/` 写一个类继承 `RuleVariantBase`（+ 需要的接口），在 `Info` 里声明 `Subsystem`(分类)/`Id`/`Requires`/`Provides`（`Overrides` 可选）。
2. 在 `rules/<分类>/<变体>/` 写 `variant.json`（requires/provides 必须与代码完全一致）+ `config.schema.json` + `tests/` 夹具。
3. `wpe verify` 自检：**平台反射发现代码里的变体，并与 `variant.json` 1:1 对账**；再查能力依赖/独占冲突/表达式函数与名字。

冷门/客制化规则：`game.json` 的 `hookType` 指向一个 C# `IHook` 实现（行动前后钩子）。开源 + AI 辅助下，写一个变体或 hook 的成本很低。

## 组合校验（verify 在加载时拦下坏组合）

- 代码里的变体实现与磁盘 `variant.json` 必须 1:1 对应（含 `requires/provides/overrides` 集合一致）；
- 每条规则的 `Requires`（能力名）必须被某条已选规则的 `Provides` 覆盖；
- **独占能力提供者不得多于一个**（同能力只能选一个）；
- `requiresVariants`（如 `map:hexGrid`）必须选到该变体；
- 不同规则重复提供同一函数/效果名 → 报错（除非声明 `overrides`）；
- 表达式里的函数必须已注册（error）；引用的名字必须在 `NameContract` 中（未知 → warning）；
- 剧本部署格/进场格必须在地图内。

这些防线保证：**配置写错是在 `verify` 时报错，不是开一局才炸**。
